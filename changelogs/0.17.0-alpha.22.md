# Lunil 0.17.0-alpha.22

## Rebuild CPU and residency on multi-million-line workspaces

- Debounced workspace rebuilds are now incremental. Per-module analysis results are
  retained in a byte-budgeted cache whose keys encode each module's content hash and
  every dependency's export hash: an edit re-analyzes the edited module and its
  dependents, while unchanged modules hit the cache instead of the CPU as long as
  they fit the budget. Cache size estimates now track the real cost of retained
  compiler models, so the budget bounds actual memory rather than underestimating it.
- A race that could store an empty workspace snapshot when the initial disk load
  finished around the first debounced rebuild is fixed: rebuilds that captured the
  document set before a load completes are rejected and retried.
- Background rebuilds no longer copy the whole corpus: workspace documents wrap each
  file's canonical UTF-8 buffer without duplicating it, so a reindex over hundreds of
  megabytes of sources stops allocating a second full copy per pass.
- The language server's background analysis runs with two cores of headroom (minimum
  two workers) so hover, completion, and navigation stay responsive while a full
  workspace index builds.
- Closed documents' source bytes now follow a 512 MB least-recently-used residency
  budget: cold files drop their buffers after a rebuild and reload transparently from
  disk on next use. Open documents and virtual documents stay resident. Combined with
  data-file exclusion, the steady-state footprint of a very large workspace is the
  code corpus's hot set plus bounded caches instead of every scanned file.
