# Lunil 0.12.0

Lunil 0.12.0 is the stable production hot-update and analysis-embedding release. It adds an opt-in,
fail-closed deployment path for hosted and game-loop workloads without changing the default Lua
language target or enabling CLR access for existing hosts.

## Production hot update

- Added canonical Patch Bundles with bounded readers, payload hashing, ECDSA P-256 signatures,
  expiring manifests, time-aware key rotation and revocation, and durable target-scoped replay
  protection.
- Added signed forward/rollback intent, verified-signer rollback authorization, capability admission,
  exact-match target selectors, revision classification, and dependency-aware preflight. Rejected
  admission does not execute candidate code or consume a replay reservation.
- Added `lunil patch pack`, `verify`, `inspect`, `dry-run`, and `diff` workflows, including bounded
  multi-key trust-store files.
- Added background preparation and game-loop safe-point commits with atomic multi-module and
  multi-State ring publication, target traffic isolation, bounded quiescence, health checks, and
  rollback.
- Added pinned cross-process prepared/health barriers for fixed participant sets and quorum policies,
  with file-backed and external-control-plane stores that fail closed on timeout, conflict, corruption,
  or peer failure.

## Game state and resource continuity

- Added signed migration schemas for state paths and runtime resources. `PatchTable` preserves live
  table identity while adopting candidate entries, metatables, weak-table behavior, and compatible
  function versions; GC-safe journals restore the previous object graph after a rejected rollout.
- Added stable host-resource handles with explicit leases, single ownership, deferred disposal, and
  CLR bridge integration for non-copyable engine and native objects.
- Added generation fencing for module-owned CLR delegates, event subscriptions, tasks, coroutines,
  native continuations, and host-polled timers. Candidate work remains pending until publication,
  and superseded generations fail closed.
- Added coroutine and timer continuation policies, timer skip/coalesce/bounded-catch-up scheduling,
  active-resource rejection, and reversible lifecycle adapters for external resources.

## Operations and reliability

- Added bounded preparation concurrency and queues, configurable pause and lifecycle budgets, hard
  limits across bundle and migration inputs, and Activity/Meter telemetry for deployment outcomes.
- Added exclusive, hash-chained deployment journals with stable-storage flushes, retention-aware
  compaction, crash recovery, and explicit traffic-restoration state.
- Added host-wide generation snapshots and rollout guards for transition residue and stale-resource
  budgets before replay acceptance or distributed health acknowledgement.
- Added bounded, thread-safe rollout history whose summaries do not retain Lua values, candidate
  modules, execution results, raw exceptions, or patch payloads.
- Added bounded candidate JIT warmup with conservative live-profile remapping, hot-function ordering,
  Tier 1 and profile-qualified Tier 2 compilation, deadlines, and interpreter/NativeAOT fallback.

## Analysis embedding

- Added typed syntax facades and extensible visitors for calls, members, functions, parameters, and
  blocks while retaining the lossless syntax tree for recovery and advanced inspection.
- Added canonical serialized symbol and function keys that remain resolvable across compilation and
  workspace snapshots without depending on source offsets or transient IDs.
- Added typed call sites, symbol/global reference indexes, and immutable compilation/workspace call
  graphs that preserve dynamic, unresolved, and unreachable calls.
- Added a runnable static-analysis embedding sample and English/Simplified Chinese tutorials covering
  compiler, semantic, CFG, workspace, indexing, caching, concurrency, lifetime, and budget APIs.

## Compatibility

- Existing `ReloadModule` and 0.11 public APIs remain available. Signed transactional deployment is
  opt-in, and the CLR bridge remains disabled unless the host configures its capabilities and exact
  allowlists.
- Lua 5.4.8 remains the default language target, with explicit Lua 5.1–5.5 contracts.
- Dynamic-code-disabled, trimmed, and NativeAOT applications keep the reference interpreter path;
  candidate JIT warmup reports that it is not applicable rather than weakening deployment checks.
- Candidate code can still create host-visible effects outside the transaction journal. Keep loaders
  deterministic and place external effects behind reversible lifecycle adapters.
