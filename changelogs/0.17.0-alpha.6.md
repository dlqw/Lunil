# Lunil 0.17.0-alpha.6

## Cross-module class navigation

- Member navigation now follows `@class` inheritance chains across modules: asking
  for hover, go-to-definition, or references on an inherited member such as
  `Character:extend(...)` resolves through `---@class Npc : Character` →
  `---@class Character : GameEntity` → ... down to the module that declares the
  member, and reports its definition, signature, and call sites there.
- Member completion after a class alias lists inherited members too, not only the
  module's own exports.
- Go-to-definition on a require alias (`local Character =
  require("entities.character")`) passes through to the declaration of the exported
  class value — the `local Character = GameEntity:extend(...)` line — and hover on
  the alias shows the exported class type and its module instead of `unknown`.

## Analysis fixes

- Fixed a flow-analysis regression that swallowed every method write on annotated
  class-library tables: the `X.__index = X` prototype upgrade used to union the
  captured table back to its annotation-only snapshot, so modules like a
  `Class:extend`/`Class:new` base library exported none of their methods and none
  of their members were navigable. The upgrade now counts as shape growth and the
  full method set survives.
- Fixed annotated subclass shapes nesting the constructor result: a class declared
  as `---@class Animal : Base` initialized from `Base:extend(...)` carried the
  constructor's prototype as its shape, hiding the subclass's own members from the
  workspace export graph. The subclass's own shape is now used directly.
