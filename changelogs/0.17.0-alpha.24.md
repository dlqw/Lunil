# Lunil 0.17.0-alpha.24

## Incremental snapshot rebuilds

- Workspace rebuilds now reuse per-module snapshot projections: a module whose content
  and dependency export hashes still match its previous build is neither parsed, bound,
  nor type-analyzed again — its references, symbols, call edges, and diagnostics merge
  from the previous snapshot with only index remapping. A full reindex after an
  unrelated edit re-analyzes exactly the edited module, and an unchanged-corpus
  rebuild analyzes no module at all.
- Discovered dependencies are remembered per module, so unchanged modules skip lexing
  and parsing during discovery as well.
- Because unchanged modules no longer need their full compiler models retained for
  fast rebuilds, the language server's retained module-analysis cache shrank from a
  512 MB budget to 128 MB, covering only the changed-module working set between
  edits.
- Reused projections are re-merged so that symbol graphs, member and annotation
  reference indexes, call bindings, and per-module diagnostics are equivalent to a
  from-scratch build of the same corpus.
