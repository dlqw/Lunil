# Lunil 0.20.0-alpha.4

## Allocation-free boundary calls

The call boundary shapes that still allocated per call now run on the stack
windows the ordinary call path already uses:

- **Tail calls** no longer snapshot their arguments into an array. The argument
  window stays in the retiring frame's registers and the replacement frame is
  pushed straight from the stack, copying the arguments out before the window
  is cleared. A durable snapshot is only materialized when a pending `<close>`
  handler can suspend the frame mid-tail-call, which keeps resumption exact.
- **`__call` metamethods** on plain callables (the common single-level case,
  not chains) reuse the contiguous `[callable, arguments...]` window already
  sitting at the call site instead of materializing an argument array; chained
  and native `__call` values keep the generic resolution path.
- **Native calls** can now expose an allocation-free span fast path: results
  are written into a scratch window above the caller's registers and copied
  down, so the intermediate result array never exists. Returning `-1` falls
  back to the array body, which remains authoritative for every other path
  (resumable natives, metamethod calls, tail calls, and host invocations).
  The `math` library's single-result functions (about twenty, including the
  unary trigonometric family, `abs`, `floor`, `ceil`, `fmod`, `log`, and
  `pow`) use the new path through one shared implementation, so the array and
  span bodies cannot diverge.

Measured per-call allocations on the interpreter backend drop to the ordinary
call baseline: tail calls from about 43-75 bytes to about 3, `__call` from
about 120-184 bytes to about 8, and span-enabled native calls from about 42
bytes to about 2. Lua-to-Lua calls, vararg mechanics, and multi-value returns
were already allocation-free and are unchanged, as are observable semantics,
debug hook ordering, and public APIs.
