# Lunil 0.22.0-alpha.2

## Process-scoped services and injectable engine-host registries

The 0.22.0 architecture line continues by turning the remaining process-wide
static state into named, injectable services with explicit process defaults:

- LuaPatchCoordinator's single-rollout barrier is now an internal rollout gate.
  The parameterless constructor keeps the historical process-wide barrier shared
  by every coordinator instance; rollouts remain mutually exclusive and
  reentrancy detection is unchanged.
- LuaGodotRuntimeRegistry is now a sealed instance class. The static members
  moved to a process-wide default instance (LuaGodotRuntimeRegistry.Process);
  LuaGodotGameLoop exposes a Registry property that hosts can point at a
  dedicated registry to isolate their loops from scene-reload shutdowns.
  This is a breaking change for code reading ActiveHostCount or calling
  DisposeAll statically: use LuaGodotRuntimeRegistry.Process instead.
- The Unity package registry (LuaUnityRuntimeRegistry) mirrors the same
  instance shape; play-mode reset and editor lifecycle shutdown use the
  process instance, and LuaUnityGameLoop exposes the same Registry property.
- Semantic model derived indexes (stable symbol keys and unified reference
  lookup) are stored on the immutable snapshot itself instead of process-wide
  attachable tables; per-snapshot caching behavior is unchanged.
- The analysis seed-node closure cache is a named internal service with a
  process default; concurrent document analyses keep sharing one walk of a
  library universe. The language server's compiler warmup moved onto the
  workspace instance.

Behavior is otherwise unchanged; internal-only APIs are unaffected.
