# Lunil 0.17.0-alpha.21

## Data-file exclusion for very large workspaces

- New `lunil.analysis.exclude` setting: glob patterns such as `data/**`,
  `**/*.data.lua`, or `assets/{tables,configs}/**` keep matching Lua files out of
  workspace indexing and analysis. Patterns match workspace-relative paths
  (`/`-separated); a pattern without a separator matches the file name in any
  directory; matching is case-insensitive. During workspace indexing, excluded files
  are not read into memory and not analyzed, so multi-gigabyte generated corpora no
  longer inflate residency or index time; opening one in the editor analyzes it
  anyway (see below). Changing the setting re-scans the workspace without a restart.
- New `lunil.analysis.autoDetectDataFiles` setting (on by default): very large files
  that are pure generated data — table literals of keys, strings, and numbers with no
  functions, requires, or control flow — are detected by a bounded content scan and
  kept out of indexing automatically. A 512 KB floor keeps ordinary code (and small
  config tables) untouched, and detection reads at most the first 4 MB of a file.
- Modules excluded from analysis that are still required by code resolve as untyped
  values instead of reporting unresolved-module diagnostics; modules present in the
  workspace always win over the exclusion list.
- Opening an excluded file in the editor analyzes it anyway; closing it returns it to
  the excluded set. Watched changes to excluded files no longer reload their contents.
- **Lunil: Show Index Status** lists excluded files with their reason (auto-detected
  data or pattern match) alongside failed and pending files.
