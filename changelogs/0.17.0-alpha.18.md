# Lunil 0.17.0-alpha.18

## Annotation-class instance members

- Instances typed through annotation returns (`---@return Logger` followed by
  `local logger = Logger.new(...)`) now resolve members: go-to-definition and hover on
  `logger:info(...)` reach the class's declaring module. The class-reference type these
  annotations produce was not part of the member resolution chain, so every call site
  on such an instance reported "no definition".
- Chained receivers (`self.logger:info(...)`) resolve through the engine's recorded
  member-chain types instead of only the head symbol, so fields that hold class
  instances navigate across modules.
- Hover on a class instance — an annotated instance, a constructor result, or a loop
  variable over an instance array — now shows the full class card (module link,
  inheritance, members) instead of a bare type name.
- Mixin members (`Class.mixin(Character, Movable)`) resolve through the mixin source
  module's exports, so `self:installMovable(...)` and mixin-provided methods such as
  `takeDamage` navigate to their definitions.
- Runtime-extended classes without a `---@class` annotation chain through their
  `local X = Y:extend(...)` edges, so `CombatSystem:new(...)` finds the library's
  constructor; classes exported from namespace modules (`return { World = World }`)
  expose their methods (`world:query(...)`) to importers.
- Union element types no longer drop named class instances when an anonymous open
  instance (an unannotated `extend` result) is a sibling member, which had collapsed
  mixed arrays and hidden `systems[5]:start(...)`-style members.
- Annotated class fields resolve along the declared base chain
  (`---@field bus EventBus` on a base class), and a changed cross-file declaration
  surface now invalidates cached document analyses like a changed member surface does.

## Known diagnostics impact

- Stricter instance typing can surface new diagnostics: `---@return` annotations are
  honored literally (a query annotated `Entity[]` is checked as `Entity[]`, so
  mismatched downstream uses are flagged), and calls to members that do not exist on
  a module's exports are reported as before.
