# Lunil 0.19.0

Lunil 0.19 keeps the 0.18 entry points source compatible and hardens the host integration
boundaries: host CLR exceptions are contained as Lua errors, the JIT requirement policy fails
closed, resource bookkeeping stays bounded across hot reloads and FFI teardown, and the debugger
correlates requests by their protocol id. The binary chunk readers share one parsing core with
unified resource limits, three core subsystem files were split by responsibility with no behavior change, and
runtime error forensics moved to a dedicated internal class. See the
[migration guide](../docs/migration-0.19.0.pub.md) for upgrade details.

## Host exception containment

- Native functions and resumable natives that throw an arbitrary CLR exception fail the enclosing
  protected call with a Lua error naming the exception type and message (for example
  `System.IO.IOException: disk full`); `pcall` catches the failure and execution remains usable.
  Unprotected paths surface a `LuaRuntimeException` instead of the raw host exception type.
- `LuaClrException` derives from the new public `Lunil.Runtime.LuaHostException` base and keeps
  its typed pass-through contract for host-level lifecycle violations.

## Fail-closed JIT requirement

- `LuaHostExecutionBackend.Auto` with the `RequireJit` JIT policy throws
  `PlatformNotSupportedException` at `LuaHost` construction on runtimes without dynamic-code
  support instead of silently falling back to the interpreter.

## Bounded resources for long-running hosts

- Invalidating compiled modules (hot reload, patch deployment) reclaims JIT generation tracking
  and sweeps the oldest invalidated function entries beyond an internal bound; the observable
  `Invalidated` function state and publication guards are unchanged.
- Disposing an FFI context closes every live native buffer and returns the allocation budget;
  buffers carry a finalizer as a last-resort release path.
- `collectgarbage("setpause")` and `collectgarbage("setstepmul")` now take effect with PUC-style
  ratio semantics; default pacing is unchanged.

## Unified binary chunk handling

- The Lua 5.1–5.5 chunk readers share one byte-level parsing core, and the version exceptions
  derive from the new public `LuaChunkFormatException` base so hosts can catch any chunk failure.
- New `LuaChunkCodec` is the single dispatch point from a chunk format to the version converters
  and writers, and the canonical Lua 5.4 reader options translate automatically for formats with
  dedicated option records.
- Lua 5.1 and 5.2 readers adopt the shared default resource limits (relaxation only).

## Debugger and tooling

- The game-loop DAP attach relay correlates requests by their `id` field, fixing response
  mismatches for clients whose request `id` differs from `seq`.
- The class-factory source scanner is now the public `LuaClassFactoryScanner` in Lunil.Analysis.
- The debugger adapter tests poll conditions with bounded retries instead of fixed waits.

## Internal quality

- The execution engine (5,600 lines), the tiered JIT registry (4,500 lines), and the Lua 5.1
  chunk adapter (1,000 lines) were split into per-responsibility files with zero behavior change,
  and runtime error forensics moved to a dedicated internal class with an error-kind channel
  replacing message-prefix sniffing for central producers.
- A contract test keeps the host JIT statistics mirror in lockstep with the JIT statistics record.
