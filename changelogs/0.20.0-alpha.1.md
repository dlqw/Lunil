# Lunil 0.20.0-alpha.1

## Interpreter value and arithmetic fast paths

This prerelease starts the interpreter performance line. Numeric execution in the
reference interpreter resolves through direct primitive-tag checks instead of
re-deriving the value kind for every operator:

- `LuaValue.Kind` compares the integer, float, nil, and boolean tags by frequency
  before the reference-type switch, so numeric values resolve with the fewest
  comparisons; number consumers such as `TryToNumber`, `IsNumber`, and
  `NumberEquals` use the integer/float tag checks directly instead of computing
  full kinds.
- Arithmetic, comparison, equality, and integer bitwise operations dispatch to the
  same specialized integer/float/mixed helpers the compiled tiers use, before the
  generic operator tables and string-coercion rules. The generic path is unchanged
  for strings, metamethods, and mixed-type operands, so version profiles keep their
  exact coercion semantics.

Measurements on the interpreter backend (win-x64, .NET 10) show the value-kind
micro benchmark dropping from about 27 ns to about 10 ns per operation, with
warm numeric loops improving correspondingly. Behavior, public APIs, and binary
compatibility are unchanged.
