# Lunil 0.17.0-alpha.14

## Hover cards

- Class hover cards are restructured: a Lua signature header, then the defining module
  and the full inheritance chain as labeled rows, the leading doc comment, and member
  groups separated by horizontal rules.
- Every name on a class card is now a link: module names, each base class in the
  inheritance chain (`Character` extends `GameEntity` extends `Entity`), member names,
  and inherited members all navigate to their declaration site. Previously only member
  names were links; inheritance was plain text.
- Simple hovers dropped noise suffixes (`member`, bare resolution kinds) and use
  readable labels; the resolution-kind line (`local`, `global`, `upvalue · captured`)
  remains on identifier hovers.

## Standard library documentation pages

- The readonly builtin library is split into per-library pages served as virtual
  documents: `lunil-builtin:base.lua` (global functions), `math.lua`, `string.lua`,
  `table.lua`, `os.lua`, `io.lua`, `coroutine.lua`, `utf8.lua`, and `debug.lua`.
  Go-to-definition on a stdlib member opens the page that defines it at the exact
  member, instead of one large `lua` document.
- Builtin pages are Lua documents: the extension syncs them to the language server, so
  pages receive full semantic highlighting (types, functions, annotations), symbol
  navigation, and hovers — not plaintext. The Lua 5.1 `unpack` global is declared
  directly instead of aliased through `table.unpack`, and `table.unpack` gained its
  own annotated signature.

## Localization

- New `lunil.locale` setting (`auto`, `en`, `zh-cn`, default `auto`): hover card
  section labels, signature-help documentation, Lunil menu entries, status bar text,
  and index-status messages render in Simplified Chinese when selected. `auto` follows
  the VS Code UI language, and switching applies without restarting the server.
- The server also accepts a `locale` initialization option for other editor clients.

## Host-injected APIs

- New `lunil.workspace.library` setting: read-only folders of LuaLS-style `---@meta`
  declaration stubs describing globals and classes a host (C++, C#, Unity, Godot, a
  game engine) injects at runtime. Stub globals seed every analysis, so chains like
  `Game.Player.Move()` keep types, doc comments, member completion, and signature
  hovers instead of degrading to `any`.
- Stub folders contribute classes and modules as well: `---@class` declarations in
  stubs join the workspace declaration map (type-name navigation, inheritance), and
  `require` can resolve modules inside library folders. Editing a stub and running
  **Lunil: Reindex Workspace** picks up the changes without a restart.
- This complements the existing machine-generated host contract JSON
  (`lunil.hostContractPath` / `lunil.hostContractJson`); stubs are the hand-written and
  community-format path.
