# Lunil 0.22.0-alpha.4

## Compile-time generated native FFI bindings

The 0.22.0 architecture line adds a source generator for native FFI bindings,
mirroring the CLR binding generator:

- Declare bindings with one assembly attribute per symbol, for example
  [assembly: LuaFfiGenerateBinding("fixture", "add", "i32(i32,i32)")].
  The generator parses the signature at compile time, emits a strongly typed
  native delegate plus an address-resolved invoker, and produces
  Lunil.Generated.LuaFfiGeneratedBindings, an ILuaFfiBindingProvider that
  registers every declared symbol deterministically.
- Generated bindings run without runtime delegate generation: the runtime
  resolves the symbol from the loaded library and the generated invoker calls
  through Marshal.GetDelegateForFunctionPointer with the compile-time delegate
  type. Bound symbols no longer touch Delegate.DynamicInvoke, and they work
  on NativeAOT and trimmed runtimes.
- The binding model gains LuaFfiAddressedNativeInvoker and an addressed
  constructor overload on LuaFfiNativeBinding; hand-registered bindings are
  unchanged. Libraries whose bindings all resolve their own address skip the
  native load exactly as before, while libraries with address-resolved
  bindings load their handle so symbols can be resolved.
- The generator ships as an analyzer asset of the Lunil.StandardLibrary
  package. Invalid signatures, unsupported conventions, and duplicate symbol
  requests are reported as LUNILFFI001/LUNILFFI002 diagnostics.

The dynamic signature path for unbound symbols is unchanged and still requires
dynamic-code runtimes.
