# Lunil 0.17.0-alpha.5

## Annotation highlighting

- LuaLS/EmmyLua annotations now receive semantic tokens instead of plain comment
  coloring: `@class`/`@param`/`@field`/... tag keywords are highlighted as
  annotation keywords, declared class, alias, enum, field, and parameter names
  carry the declaration modifier, and every type expression (`Point`,
  `number|string`, `fun(cb: fun(): boolean)`, `{label: number}`) is highlighted
  with distinct type, string, and number token kinds.
- The parser now reports exact source spans for annotation tag keywords, names,
  and type-expression labels; these spans are part of the public annotation
  syntax API (`TagSpan`, `NameSpan`) for tools that need to address annotation
  elements.
- The VS Code extension ships `semanticTokenScopes` mappings for the new token
  kinds so themes color annotations consistently.

## Find references

- Member references now report cross-file hits instead of same-file matches
  only: asking for references on a module member (`M.f` at its definition or
  `util.f` at a call site) returns the exported definition, precise call sites
  resolved through the workspace export graph, and every same-named member
  reference across the workspace. This also fixes an internal error that could
  occur when asking for references on a non-function exported field.
- Global names (for example `function helper() ... end` called from other
  files) support find references workspace-wide and go-to-definition jumps to
  the global's first write site.
- References on a `require("...")` string list every require site of that
  module across the workspace, including the current one.

## Index status

- The index status picker is now interactive: failed documents show the actual
  failure reason, offer a per-file retry button, and a **Retry Failed** action
  re-analyzes everything that failed; a **Reindex Workspace** action and title
  bar buttons are available directly from the picker.
- Reindexing now updates per-document index status: documents queued as pending
  resolve to indexed once the workspace snapshot is rebuilt, instead of staying
  pending forever.
- Analysis failures are captured with their reason instead of escaping
  silently; a document can no longer get stuck in an "in progress" state, and
  failed files become retryable.

## Resource efficiency

- Per-request hot paths no longer rescan the whole semantic model: symbol type
  lookups and require-call scans are computed once per document version and
  reused across hover, completion, references, and token requests.
- Module-name to URI resolution uses a reverse index rebuilt only when the
  document set changes, removing a full workspace scan per resolved location.
- Semantic token responses are identified by document version: unchanged
  documents answer semantic token delta requests with an empty edit set instead
  of resending the full token array, and the per-request content hash is gone.
- Document analyses and cached token results are bounded by recency and follow
  their documents out of the workspace, keeping long sessions from growing
  without limit. Reindexing reuses each document's cached UTF-8 bytes instead
  of re-encoding every file on each rebuild.
- The language server now runs with server garbage collection, keeping
  indexing bursts off the request loop while DATAS shrinks heaps when idle.
