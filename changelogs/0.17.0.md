# Lunil 0.17.0

## Workspace-scale analysis

- Incremental snapshot rebuilds: a module whose content and dependency export hashes
  still match its previous build is neither parsed, bound, nor type-analyzed again —
  its references, symbols, call edges, and diagnostics merge from the previous
  snapshot. An edit re-analyzes the edited module and its dependents only; an
  unchanged corpus analyzes nothing.
- Table-mutation propagation no longer deep-copies the type universe per write:
  type graphs rewrite with structural sharing, and workspaces with dense table
  writes finish indexing instead of consuming unbounded CPU and memory. Generated
  data files with tens of thousands of entries analyze in linear time, and
  propagation carries its own budget with a single LUA6010 warning on adversarial
  graphs.
- New `lunil.analysis.exclude` setting (glob patterns such as `data/**`) and
  `lunil.analysis.autoDetectDataFiles` (on by default) keep generated data files out
  of indexing; very large workspaces no longer pay residency or index time for them.
  Opening an excluded file still analyzes it.
- The language server's three residency budgets — retained module analyses,
  closed-document sources, and cached document analyses — now scale with the memory
  the runtime grants the process instead of fixed constants, staying under a quarter
  of the available memory combined.
- Workspace snapshots share interned strings across rebuilds through a weak,
  thread-safe interning pool, so rebuilds cannot strand duplicate copies of
  unchanged names and symbol keys.
- Documents load as UTF-8 bytes and materialize UTF-16 views lazily; closed-document
  sources follow a least-recently-used residency budget and reload from disk on next
  use. Startup waits for the initial declaration scan with a timeout instead of
  hanging, and rebuild stores are guarded against races and lock-order inversions.
- The Lunil status item shows live per-phase indexing counts (`reading files
  1234/26000`, `analyzing n/total`) with excluded/failed/pending breakdowns, and the
  index-status picker lists failures with reasons and retry actions.

## Navigation and hover

- Go to definition, find references, and hover now cover member references
  (`module.field`, `object:method`, `t["key"]`), require strings and aliases,
  globals, class values, and type names inside annotations — across the whole
  workspace through the export and annotation indexes.
- Hovering a class, a class instance, or a type name shows a full class card: the
  signature header, module, declared and runtime inheritance chains, member
  signatures with doc comments, inherited members grouped per base, and links into
  definitions. Primitive annotation types carry short bilingual descriptions.
- The embedded Lua standard library — globals, `string`, `table`, `math`, `os`,
  `io`, `coroutine`, `utf8`, and `debug` — is defined with real annotated
  signatures. Hover shows signature plus documentation, completion lists annotated
  members, and go-to-definition opens per-library readonly pages that receive full
  semantic highlighting.
- LuaLS/EmmyLua annotations receive semantic tokens: tag keywords, declared names,
  and full type expressions are colored, and the extension ships theme mappings for
  the new token kinds.
- New `lunil.locale` setting renders hover cards, menus, and status messages in
  Simplified Chinese (`auto` follows the editor).
- New `lunil.workspace.library` setting points at read-only folders of LuaLS-style
  `---@meta` stubs describing host-injected globals and classes, giving chains like
  `Game.Player.Move()` types, docs, completion, and navigation.

## Unannotated analysis

- Metatable-based classes without any annotation now carry instance types end to
  end: constructor calls return instances whose members resolve through the class
  table and `__index` inheritance, powering completion, hover, and navigation.
  Runtime `local X = Y:extend(...)` edges and mixins join declared `---@class`
  bases in inheritance resolution.
- `require` results carry the required module's exported type in editor analyses:
  aliases, constructor calls, and member chains keep their types across module
  boundaries, and analyses are invalidated when exported types change.
- Member checks consult the workspace's runtime knowledge: annotation-declared
  classes expose the members their declaring modules write, including inherited and
  mixin members; runtime metamethods satisfy operator checks; mutual `@class`
  references resolve lazily instead of widening to unknown.
- Flow-analysis fixes: `type(x) == "number"` guards no longer leak past early
  returns, any/unknown arithmetic stays dynamic, and assignability accepts the table
  idioms real projects use (runtime class tables, `setmetatable` results,
  named-function tables, string-keyed enums, nil deletes).

## Compiler performance

- Removed quadratic scaling from the annotation-driven analyzer on large chunks. On the
  repository's front-end benchmark fixture — a generated 2 MB source with tens of thousands of
  functions (`dotnet run --project benchmarks/Lunil.FrontEnd.Benchmarks -c Release -- --sizes=2097152`)
  — analysis drops from about 46 seconds to about half a second and analysis-stage allocations by
  roughly two orders of magnitude. These numbers are fixture- and machine-specific, not a general
  guarantee; results depend on hardware and workload.
- Constant-time symbol lookup during binding, exact-size syntax node construction,
  buffer-reusing lexer trivia, and a public `SourceText.GetLineIndex(int)` helper
  for hot line attribution. No language or IR behavior changes; binary chunk output
  is byte-identical.

## VS Code extension

- Reworked Lunil status item with state icons, live indexing progress, and a Lunil
  menu (index status, reindex, cache, settings); a five-step Get Started walkthrough;
  curated Lua and Lunil annotation snippet libraries; indentation and comment
  continuation rules; and a word pattern that selects full `a.b.c` chains.
- Quick fixes can suppress a diagnostic workspace-wide, index status lists failed
  files with reasons and retry actions, and a file-watcher leak on server restarts
  is fixed.
- Fixed a crash on `$/cancelRequest` racing a completed response and a hang when
  every registered workspace folder was empty or missing on disk.

## Compatibility

- `0.17.x` becomes the stable line; the 0.16 API surface remains source compatible
  and additive: `SourceText.GetLineIndex`, annotation `TagSpan`/`NameSpan` spans,
  and `LuaWorkspace.StringInterner` with `LuaWorkspaceStringInterner` are new.
- The `api/0.17.0/` baseline is frozen.
- The language server enforces `lunil.server.gcHeapHardLimitPercent` on top of
  server GC; residency budgets are now adaptive (previously fixed 128/512/384 MB).
