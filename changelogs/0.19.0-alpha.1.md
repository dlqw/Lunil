# Lunil 0.19.0-alpha.1

## Host exception containment

Native functions and resumable native closures that throw an arbitrary CLR exception now
fail the enclosing protected call with a Lua error naming the original exception type and
message (for example `System.IO.IOException: disk full`) instead of letting the exception
terminate the scheduler and the host process. `pcall` catches these failures, execution
remains usable afterwards, and unprotected paths surface a `LuaRuntimeException` carrying
the converted error rather than the raw host exception type.

CLR interop failures keep their existing contract: `LuaClrException` (now derived from the
new public `Lunil.Runtime.LuaHostException` base) still crosses the execution boundary as a
typed CLR exception, because it signals a host-level lifecycle violation rather than a
script-recoverable condition.

## RequireJit fails closed without dynamic code

`LuaHostExecutionBackend.Auto` combined with the `RequireJit` JIT policy no longer falls
back to the interpreter on runtimes without dynamic-code support. `LuaHost` construction
now throws `PlatformNotSupportedException` with an explicit diagnostic, matching the
existing behavior of the explicit `Jit` backend on such runtimes.

## Unified binary chunk resource limits

The default resource limits of the version-specific binary chunk readers now come from one
shared source. Lua 5.1 and 5.2 readers adopt the same defaults as Lua 5.3/5.4/5.5 —
prototype depth 128 → 200, instruction count 4,000,000 → 10,000,000, upvalue count
100,000 → 1,000,000, string bytes 16 MiB → 64 MiB, and debug entry count 2,000,000 →
10,000,000 — a relaxation only: chunks accepted before remain accepted, and previously
rejected large-but-valid chunks now load.
