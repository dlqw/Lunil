# Lunil 0.22.0-alpha.7

## State-owned semantic operations

LuaRuntimeOperations becomes a sealed instance service owned by each LuaState
(reachable as state.Operations) instead of a static class with a state
parameter on every method:

- GetIndex, SetIndex, Unary, Binary, and ResolveCall drop their leading state
  argument; the service captures the state's immutable version profile
  (bitwise string coercion, ordering rules, __le fallback, arithmetic string
  coercion) at construction, so the per-version branches read captured fields
  instead of re-reading state properties.
- The generated-code ABI entry points (LuaCodegenAbiV1-V5) keep their exact
  static signatures; their internals now dispatch through the owning state's
  operations service.
- The primitive fast-path resolvers shared with the compiled tiers
  (TryResolvePrimitiveBinary/Unary) remain pure static functions, as do the
  stateless helpers on the execution engine partials; value-level computation
  in LuaValueOperations is unchanged.

This is a breaking change for embedders calling the static
LuaRuntimeOperations methods directly: obtain the service from the state
(state.Operations) and drop the state argument.
