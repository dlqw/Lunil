# Lunil 0.16.0-alpha.6

## Cross-process debugger attach transport

- `LuaGameLoopHost.StartDebugServer(pipeName)` exposes a DAP endpoint over a named pipe
  (`LuaGameLoopDebugServer`): breakpoints, pause, stepping, stack, scope, variable, thread, and
  disconnect requests are served in-process with the host, and `stopped` events are published
  when a turn suspends for the debugger.
- Resume commands are queued back into the game loop (tick-driven debug resume), so the loop
  stays the single execution driver: a resumed turn runs through `LuaHost.ResumeDebuggedThread`,
  which activates the interpreter debug-pause path (`LuaExecutor.ResumeDebugged`).
- The debug adapter gains attach mode: `lunil-debug-adapter --stdio --pipe <name>` connects to
  the host pipe and relays DAP frames verbatim between the client and the host, preserving
  request sequence numbers so responses match the client's pending requests exactly.
- The VS Code extension passes `--pipe <debugPipe>` for attach configurations (new
  "Attach to host" snippet); attach requires the interpreter execution backend (the CIL JIT
  backend does not dispatch debug hooks) and rejects JIT hosts with a clear error.

## Execution-engine stack margin

- The host debugger checkpoint now tests a hoisted session flag instead of re-reading the
  state's debug session on every instruction of the hot loop (no per-instruction cost when no
  debugger is attached).
- The managed C-stack guard (`MaximumCStackDepth`) is tuned so deep `coroutine.close` chains
  and error cascades raise "C stack overflow" with margin on the default 1 MB thread stack
  instead of exhausting the managed stack first.
