# Lunil 0.17.0-alpha.19

## Analysis performance on large workspaces

- Table-mutation propagation - the pass that keeps aliased variables consistent after
  `t.x = v` member writes, index writes, `setmetatable`/`rawset` calls, and dynamic
  calls that let tables escape - no longer deep-copies the surrounding type universe
  on every write. Type graphs are now rewritten with structural sharing: unchanged
  nodes keep their identity, shared sub-graphs are visited once per propagation, and
  the global-environment scan only runs when the mutated table is reachable from a
  published global value. Workspaces with dense table writes finish indexing instead
  of consuming unbounded CPU and memory.
- Alias behavior is unchanged: writes still propagate across local aliases
  (`local b = a`), global aliases (`B = A`), and through globals reached via locals.
- Propagation carries its own per-document analysis budget: adversarial type graphs
  stop updating
  remaining aliases and report a single LUA6010 budget warning instead of running
  unbounded.
- Generated data files with tens of thousands of table entries analyze in linear
  time. Bracket-literal key and value unions now fold incrementally instead of as one
  bulk pairwise pass, and tables that keep receiving new named members past 4,096
  absorb further writes into their map key/value types while already-stored members
  keep their declared precision.
