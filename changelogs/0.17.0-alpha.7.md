# Lunil 0.17.0-alpha.7

## Class-library diagnostics

- Member checks now consult the workspace's runtime knowledge: annotation-declared
  classes expose the members their declaring modules write at runtime
  (`Base:extend`, `Vec2.new`, `Class.mixin`), including inherited members along the
  `@class` chain and mixin edges, so idiomatic class-library code no longer reports
  "has no known member" for methods annotations do not declare.
- Runtime metamethods satisfy operator checks: `Vec2 + Vec2` works when the defining
  module assigns `Vec2.__add`, using the exported signature's return type.
- Mutual `@class` references (entities holding components that point back) resolve to
  lazy class references instead of reporting a recursive declaration and widening the
  type to unknown; the misplaced cross-file span on that diagnostic is gone, and
  external declarations no longer produce diagnostics positioned in the analyzed file.
- Analyses cached before the workspace index existed are rebuilt once the index is
  available, so diagnostics published right after startup reflect workspace knowledge
  without waiting for the first edit.

## Flow and assignability

- Arithmetic with an any/unknown operand stays dynamic instead of claiming `number`,
  which poisoned every later member access on the result.
- `type(x) == "number"` guards no longer leak the narrowed branch past an early
  return; nil-guard returns (`if x == nil then return end`) narrow the member path.
- Assignability now accepts the table idioms Lua projects use: empty-table
  initializers for annotated slots, runtime class tables and `setmetatable(...)`
  results where the annotated class is expected, named-function tables where a
  string-keyed map is expected, string keys for string-backed enums, number values
  for integer slots, and nil writes that delete map entries.
- Writing a member of a class-typed value keeps the declared view instead of
  collapsing it to a single-field shape; dynamically indexed tables resolve to their
  value union instead of an opaque unknown.
- Class-level generic parameters (`---@class Pool<T>`) may be referenced from method
  annotations without a function-level `@generic`.
