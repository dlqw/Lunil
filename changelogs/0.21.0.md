# Lunil 0.21.0

Lunil 0.21.0 adds a tier 0.5 dispatch layer to the reference interpreter.
Hot Lua functions decode once into a private compact instruction stream
and execute through a specialized dispatch loop with local program
counters, direct register access, and inline call, tail-call, and table
fast paths. A new opt-in performance profile skips cross-state
validation inside mutation hot paths. Public APIs stay source and
binary compatible; no migration is required.

## Tier 0.5 dispatch layer

- Function versions decode their canonical IR once into a compact
  instruction stream cached on the version. Arithmetic and bitwise
  operators, comparisons, moves, constants, branches, metatable-free
  table reads and writes, and integer numeric-for loops run inline with
  operator-specialized opcodes and inline integer and float immediates.
  Every other instruction falls back to the canonical executor one
  instruction at a time, so semantics, debug hooks, coroutines,
  `<close>` handling, and error reporting are unchanged.
- Ordinary Lua-to-Lua calls push the callee frame directly from the
  stack argument window and rebind the dispatch loop without a scheduler
  round trip; `return f(args)` tail calls replace the frame in place.
  Frames with pending close handlers, protection state, or non-reference
  routing keep the canonical paths.
- The dispatch loop caches the stack's value array and mirrors the frame
  top in a local between safepoints. Instruction-budget accounting stays
  exact per instruction, and heap safepoint requests are honored on
  every instruction as before.

## PerformanceProfile

- `LuaInterpreterOptions.PerformanceProfile` selects `Balanced` (the
  default, unchanged behavior) or `Unchecked`. The `Unchecked` profile
  skips cross-state and use-after-collect validation inside write
  barriers and table lookups and stores while keeping the checks at
  execution and host boundaries, so isolated misuse still surfaces at
  the boundary instead of the faulting store. Both profiles enforce the
  instruction budget and identical Lua semantics.

## Measurements

On the release benchmark suite (win-x64, .NET 10, interleaved medians
against 0.20.0), the interpreter runs about 2x faster on the integer
arithmetic loop, 1.8x on `mandelbrot`, about 1.5x on call-heavy
recursion, and about 1.4x on table-access workloads; tail-call-heavy
recursion and the compiled execution paths are unchanged. The
`Unchecked` profile adds roughly 10% on table-dense workloads. The
workload sources and measurement commands ship in the repository's
`benchmarks/` directory for independent reproduction.
