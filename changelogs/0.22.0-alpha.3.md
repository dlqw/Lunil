# Lunil 0.22.0-alpha.3

## Reflection-free CLR interop conversions

The 0.22.0 architecture line reaches the CLR bridge: steady-state interop
conversions no longer perform runtime reflection lookups or invocations.

- The binding registry serves lookups lock-free. Registration still fails
  closed on conflicts, but per-call binding resolution no longer contends with
  or waits behind registrations.
- Task results are read through one strongly typed delegate per closed
  Task<TResult> type, computed once per type; ValueTask results convert to
  tasks the same way. Runtimes without dynamic code keep the rooted-metadata
  path, now also cached per type.
- Enum conversions use cached name tables and cached underlying-type facts
  instead of per-call Enum.Parse/GetUnderlyingType. Array and collection
  targets cache their element-type and interface-shape resolution.
- Default value-type out arguments are produced by a cached boxed-default
  factory instead of per-call Activator construction on runtimes with dynamic
  code.

The reflection fallback bridge for unbound types is unchanged in this
prerelease and remains available with RegistryThenReflection; behavior and
public APIs are unchanged.
