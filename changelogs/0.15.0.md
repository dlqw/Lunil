# Lunil 0.15.0

## Native C ABI FFI

- Added a disabled-by-default native C ABI FFI contract for explicitly configured standard-library hosts; unrestricted default behavior is unchanged.
- Added exact library and symbol allowlists, stable FFI error categories, configurable resource limits, and a replaceable native library loader.
- Added exact host-registered bindings for AOT and trimmed environments, with deterministic signature and registration validation; dynamic signature adaptation is used only where runtime dynamic code is available and fails with a stable diagnostic otherwise.
- Added an opt-in `ffi` module with `load`, `bind`, `close`, `alloc`, `free`, `read`, and `write`, plus rooted userdata metatables with `__gc`/`__close` lifecycle hooks and library close invalidation.
- Added a bounded non-variadic C ABI signature parser with scalar, pointer, and UTF-8 string types, strict Lua value conversion, and stable range and conversion failures.
- Added bounded native buffers with bounds-checked scalar and C-string read/write, pointer-sized storage, allocation budgets, and idempotent release.
- Added platform loader detail: Windows error messages, `dlerror` on Unix-like systems, and a Linux `libdl.so.2` to `libdl.so` fallback for musl-based distributions.
- Kept `package.loadlib` as an explicit unsupported Lua C module diagnostic; FFI is a separate allowlisted surface.

## Compatibility

- `0.15.x` is the stable line; existing .NET 10 host entry points remain source compatible.
- `LuaStandardLibraryOptions.Ffi` defaults to disabled; `InstallPackage(LuaState)` keeps its existing overload.
- Public API baselines add the FFI contract types under `Lunil.StandardLibrary`; no existing public member is removed.
- See the [0.15 migration guide](https://github.com/dlqw/Lunil/blob/v0.15.0/docs/migration-0.15.0.pub.md) for details.
