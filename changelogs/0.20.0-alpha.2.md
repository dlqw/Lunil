# Lunil 0.20.0-alpha.2

## Interpreter inline fast paths for the compact loop

The reference interpreter's compact loop now executes primitive operations without
returning to scheduler validation between instructions:

- Numeric arithmetic, comparisons, equality, integer bitwise operations, numeric
  negation and bitwise-not, logical-not, string length, and metatable-free table
  length resolve inline and keep the loop in its pure-chain mode, which only bounds
  checks the next program counter until a slow operation or safe point occurs.
- `GetTable` and `SetTable` on tables without a metatable use the plain array/hash
  lookup and insert paths directly. Results cannot reach `__index`/`__newindex`,
  so the resolution and metamethod dispatch layers are skipped; tables with
  metatables, strings, userdata, and any key that misses the fast path fall back to
  the previous resolution path unchanged.

Primitive failures keep the previous error contract: a faulting operation (for
example integer division by zero) leaves the program counter on the faulting
instruction, and metamethod cases keep the previous behavior. Table-heavy micro
workloads (`table.insert/remove`, `table.sort`, mixed array/hash access) improve
measurably over 0.19.0 on win-x64, with warm numeric loops down roughly 20%.
