# Lunil 0.20.0

Lunil 0.20.0 is a performance release for the Lua runtime: the reference
interpreter executes numeric, table, and metamethod code substantially faster and
the remaining per-call allocations at tail calls, `__call` metamethods, and
native-library boundaries are gone. Public APIs and binary compatibility are
unchanged; no migration is required.

## Interpreter fast paths

- `LuaValue.Kind` resolves primitive tags by frequency, and number consumers such
  as `TryToNumber` and `NumberEquals` use direct tag checks instead of computing
  full kinds for every operator.
- The interpreter's compact loop resolves primitive arithmetic, comparisons,
  bitwise operations, lengths, and metatable-free table reads and writes inline,
  staying in its pure chain instead of re-entering scheduler validation between
  instructions. Operation results that do not invoke metamethods — including
  metatable-backed table reads that find the key — commit inline; only
  metamethod calls re-validate. The loop caches the stack object, frame base,
  and heap reference that every instruction previously reloaded.

## Allocation-free boundary calls

- **Tail calls** keep their arguments in the retiring frame's window and push the
  replacement frame straight from the stack; a durable snapshot is only
  materialized when a pending `<close>` handler can suspend the frame.
- **`__call` metamethods** on plain callables reuse the contiguous
  `[callable, arguments...]` window already at the call site; chains and native
  `__call` values keep the generic resolution path.
- **Native calls** can run through an allocation-free span fast path used by the
  built-in libraries: results are written into a scratch window above the caller's
  registers and copied down, so the intermediate result array never exists. The
  array body stays authoritative for resumable natives, metamethod calls, tail
  calls, and host invocations. The `math` library's single-result functions use
  the new path through one shared implementation.

## Measurements

On the release benchmark suite (win-x64, .NET 10), the interpreter runs about
20% faster overall across the standard workloads — `mandelbrot` about 1.8x,
`control_flow` and `arithmetic` about 1.5x, and `table_access` about 1.3x faster
than 0.19.0 — while the compiled execution paths are unchanged. Per-call
allocations at the affected call shapes drop to the ordinary call baseline. The
workload sources and measurement commands ship in the repository's
`benchmarks/` directory for independent reproduction.
