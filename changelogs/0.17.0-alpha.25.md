# Lunil 0.17.0-alpha.25

## String interning and adaptive memory budgets

- Workspaces now own a thread-safe string interning pool shared by every compact
  snapshot rebuild. Reference names, symbol keys, member and annotation names, and
  call-binding strings emitted by a rebuild map onto the canonical instances the
  previous snapshot already retains, so re-analysis cannot strand duplicate copies
  of unchanged names during the rebuild transition.
- The pool's catalog is weak: canonical instances stay pooled only while a snapshot
  or projection still references them, so renames and deletions cannot accumulate
  interned strings in a long-running language server.
- The language server's three residency budgets (module-analysis cache, closed-document
  residency, and cached document analyses) now scale with the memory the runtime
  grants the process instead of fixed 128/512/384 MB constants. Small machines shrink
  toward the floors; large machines gain headroom for huge workspaces, and the three
  combined stay under a quarter of the available memory.
