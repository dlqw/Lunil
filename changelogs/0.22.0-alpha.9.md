# Lunil 0.22.0-alpha.9

## Registry-only CLR interop and reflection-free JIT tokens

Runtime reflection leaves the product paths:

- CLR interop dispatch is registry-only. The LuaClrBindingMode enum and the
  LuaClrOptions.BindingMode property are removed along with the entire
  reflection fallback bridge (member caches, reflection overload selection,
  MethodInfo/PropertyInfo invocation, reflection-built delegates, the
  AppDomain type scan, and Activator-based construction for tuples and
  collections). Allowlisted types without a registered binding now fail with
  a stable 'no registered static binding' error pointing at the binding
  generator. Enabling CLR interop without a binding registry is a
  configuration error. This is a breaking change: generate bindings with
  [LuaClrGenerateBinding] for every type you expose to Lua.
- The managed JIT backend resolves its emitted-call method tokens through
  delegates instead of Type.GetMethod: 161 token lookups across the tier-1,
  tier-2, numeric-region, and OSR compilers are now compile-time-bound
  delegate shapes. Property getters, constructors, and one instance method
  that cannot be constructed at type initialization keep their metadata
  lookups as the documented remainder inside the dynamic-code backend.
- The command-line compiler and the language server report their version
  from a compile-time generated constant instead of reading assembly
  metadata at runtime.
- A latent registry-path bug is fixed with the fallback's removal: event
  subscription now uses the bound delegate's real return type instead of
  assuming void handlers. Indexer dispatch has no registry path and
  fails closed with a member-not-found error.
