# Lunil 0.17.0-alpha.1

## Compiler front-end performance

- Removed quadratic scaling from the annotation-driven type analyzer on large chunks.
  A 2 MB source with tens of thousands of functions now analyzes in about half a
  second instead of about 46 seconds, and analysis-stage allocations drop by roughly
  two orders of magnitude. End-to-end verification of that chunk drops from about
  47 seconds to under one second.
- Flow-analysis states now share the global environment instead of copying it per
  function, scope, and branch, keeping memory growth close to linear in source size.
- Symbol lookup during binding is now constant-time per name reference instead of a
  scan over every active local, and repeated identifier names are interned once per
  chunk instead of allocating a fresh string per reference.
- Constant deduplication during lowering is now constant-time per constant instead of
  comparing against every existing constant in a function, and instruction line
  attribution no longer rescans source bytes for UTF-16 columns on every emitted
  instruction.
- The lexer reuses its trivia buffer (tokens without leading trivia no longer
  allocate one) and builds literal tokens once instead of cloning them to attach
  decoded values; string literal decoding copies its bytes once instead of twice.
- The parser builds syntax nodes from exact-size child arrays, eliminating the
  intermediate list growth and double copy per node, and computes each node's span in
  a single pass.
- Incremental reparse of a one-line edit in a 2 MB chunk drops from about 137 ms to
  about 65 ms.
- No language, IR, diagnostic, or API behavior changes; binary chunk output is
  byte-identical.
