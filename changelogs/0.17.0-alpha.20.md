# Lunil 0.17.0-alpha.20

## Workspace memory residency and scheduling hardening

- Cached document analyses now follow a byte budget (384 MB by default) with true
  least-recently-used eviction instead of a fixed entry count: small analyses no
  longer evict while a few huge ones linger, and documents open in the editor are
  pinned so interactive requests keep their analyses through background churn.
- Documents load from disk as UTF-8 bytes; the UTF-16 view and line index
  materialize only when a request needs them. A scanned workspace now pays one
  byte representation per file instead of three parallel ones, and analysis-cache
  freshness compares encodings directly.
- Startup waits for the initial declaration scan with a 120-second timeout
  instead of forever: a scan that never signals no longer hangs every analysis;
  affected requests proceed and later scans invalidate their results.
- Clearing caches no longer inverts lock order against the workspace operation
  gate (a potential deadlock between the workspace gate and analysis progress
  reporting), and rebuild result stores are guarded by document-set identity so
  an in-flight declaration scan can no longer discard the only rebuild that
  observed the library globals.
- Runtime `extend`/`mixin` discovery scans raw bytes with a hand-rolled matcher
  instead of recompiling a regex per rebuild and running it inside the workspace
  lock; full-text scans now run outside the gate, and `local` embedded inside a
  longer identifier is correctly rejected.
- Table literals with tens of thousands of entries build their member lists in a
  single pass over syntax children (no per-field array materialization) and stop
  tracking individual named members past 4,096, absorbing further entries into
  map key/value types - matching the member-write growth cap from alpha.19.
- The language server process enforces the configured managed-heap hard limit
  (`lunil.server.gcHeapHardLimitPercent`) on top of server GC, so runaway growth is
  contained by that limit during indexing.
