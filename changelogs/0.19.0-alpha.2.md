# Lunil 0.19.0-alpha.2

## Bounded JIT code-cache bookkeeping

Invalidating compiled modules (hot reload, patch deployment, explicit invalidation) now
reclaims generation tracking for content ids without live entries and bounds the compiled-
function table: once it exceeds an internal cap, the oldest invalidated tombstones are
swept. Long-running hosts that reload modules repeatedly no longer accumulate function
entries without bound. The observable `Invalidated` function state, terminal interpreter
routes, and cross-invalidation publication guards are unchanged, because invalidated
tombstones are retained until the bound is reached.

## Native FFI budget is returned deterministically

Disposing an FFI context now closes every native buffer still registered with it, releasing
their unmanaged memory and returning the allocation budget, even when scripts never freed
the buffers. Buffers also carry a finalizer as a safety net, so the allocation budget can no
longer leak for the lifetime of the process.

## collectgarbage("setpause") and collectgarbage("setstepmul") take effect

The two tuning knobs previously accepted and returned values without affecting collection.
They now map onto the logical collector with PUC-style ratio semantics: the pause ratio
(default 200) scales the allocation debt that restarts collection, and the step multiplier
(default 100) scales the per-step work. Default pacing is unchanged; the knobs only alter
collection scheduling after a script or host sets them.
