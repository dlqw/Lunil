# 0.18.1

Bug-fix release on the 0.18.0 stable line. No public API or format changes.

## Fixes

- Language Server: renaming a global variable now rewrites every reference across the
  workspace. Previously `textDocument/rename` reported rename as unavailable for globals.
- Language Server: `textDocument/prepareCallHierarchy` now returns a single call-hierarchy
  item as expected by standard clients, so call hierarchy works with them.
- Language Server: a malformed JSON-RPC message now produces a `-32700` parse error and the
  session keeps serving requests instead of terminating the server process.
- Debugger: breakpoints set by clients that send absolute source paths (such as VS Code)
  now bind and hit as expected.
- CLI: `lunil dump --kind chunk --lua-version 5.2` no longer fails with an internal error;
  Lua 5.2 chunks now dump in both text and JSON form.
- Lua 5.5: `local <const>` / `local <close>` prefixed attributes now bind the name that
  follows them and apply to every name in the declaration list, per the Lua 5.5 grammar.
- Godot: scripts running through the game-loop adapter no longer get shell execution
  (`os.execute`, `io.popen`), process termination, or environment-variable access by
  default. File access stays limited to the registered project resources; trusted access
  requires an explicit `ConfigureHostOptions` opt-in. `print` output continues to route
  through the Godot console.
- Runtime: mixed integer/float comparisons now follow IEEE semantics for negative zero,
  so `0 == -0.0` is `true` and `-0.0 < 0` is `false`, matching PUC Lua.
- Runtime: `a <= b` on Lua 5.4 and 5.5 no longer falls back to
  `not (b < a)` when only `__lt` is defined and raises the PUC "attempt to compare"
  error instead; Lua 5.1, 5.2, and 5.3 keep the fallback, matching their PUC
  reference implementations. Lua 5.1 now also rejects ordering between different
  types outright, matching PUC Lua 5.1.
- Runtime: canonical modules written to Lua 5.4/5.5 chunks now raise the RETURN close
  flag whenever a to-be-closed variable is live, so `__close` runs on return when such
  a chunk executes on PUC Lua.
- Lua 5.5: closures created inside numeric `for` loops now capture the control variable
  correctly across the Lua 5.5 chunk boundary; the loop register shift previously left
  the closure's upvalue descriptor pointing at the wrong parent register.
- Chunk readers: truncated Lua 5.1, 5.2, and 5.3 chunks that end where a companion
  instruction (JMP or EXTRAARG) is required now fail with a chunk-format error instead
  of an internal index exception.
- Parser: incremental reparsing an edit appended directly at the end of the last
  statement (for example typing `3` after `x = 12`) now produces the same tree and
  diagnostics as a full reparse.
- Parser: string escape version diagnostics (`LUA2016`) now also apply to string
  arguments of sugar calls such as `f"\x41"`, and long-string arguments no longer
  raise them.
- `string.format`: `%e`, `%E`, `%g`, and `%G` now print at least two exponent digits
  and render non-finite values as `inf`/`-inf`/`nan` (`INF`/`NAN` for the uppercase
  conversions), matching C printf and PUC Lua instead of .NET's `Infinity`/`NaN`.
