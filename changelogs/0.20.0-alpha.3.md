# Lunil 0.20.0-alpha.3

## Compact-loop structural overhead and immediate-result chaining

The interpreter's compact loop now keeps running through immediate operation
results instead of returning to scheduler validation between them, and caches
the loop-invariant state that every instruction previously reloaded:

- Operation resolutions that do not invoke metamethods — including generic-path
  hits such as metatable-backed table reads that find the key — commit their
  result inline and advance the program counter directly. Only resolutions that
  push a metamethod call re-enter scheduler validation.
- The stack object, frame base, and heap reference are hoisted out of the
  instruction loop; register reads and writes go through the cached values
  instead of walking the thread and frame chains on every operand access.
- Immediate metamethod-call paths check the resolution inline, so tables with
  metatables pay only the resolution dispatch they paid before.

Calibrated six-round medians against 0.19.0 (win-x64, .NET 10): the interpreter
backend improves about 21% geometric mean across the nine standard workloads
(`mandelbrot` about 1.9x, `arithmetic` and `control_flow` about 1.5x,
`table_access` about 1.3x), while tier1, tier2, and both loop-OSR configurations
show no regressions (tier1 about 7% faster on the same suite). Behavior, public
APIs, and binary compatibility are unchanged.
