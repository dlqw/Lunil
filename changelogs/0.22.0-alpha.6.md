# Lunil 0.22.0-alpha.6

## Instance-owned JIT backend caches and warmup state

The managed JIT backend no longer keeps memo, warmup, or counter state in
process-wide static fields:

- The module-keyed memos for canonical IR verification, register liveness,
  numeric regions, codegen plans, and module content identities became
  instance caches owned by the tier compilers and the tiered JIT registry.
  The registry adopts the well-known tier-1, tier-2, and loop-OSR compilers'
  caches, so one executor keeps sharing its analyses exactly as before;
  custom injected compilers get their own deterministic caches.
- The one-time compiler warmups (ABI resolution plus a full compile of a
  trivial module for tier 1, an end-to-end specialized loop for tier 2, and
  the OSR emitter type preparation) run exactly once per compiler instance.
- The emit sink's name-to-method runtime ABI cache moved to a long-lived
  runtime ABI component owned by the tier-1 compiler; the public static plan
  entry points remain deterministic and now compute through a transient
  cache.
- The direct-call counter sink no longer allocates process-global ids; its
  thread-static fast path validates the cached shard by sink reference and
  stays lock-free.

Tier eligibility, promotion thresholds, and fallback semantics are unchanged.
All internal changes; public APIs and API baselines are unchanged.
