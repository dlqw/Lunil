# Lunil 0.22.0

Lunil 0.22.0 restructures the engine around instance-owned components and completes the
compile-time binding story: CLR interop dispatch becomes registry-only, native FFI symbols can
be bound by a source generator, and runtime reflection leaves the product paths. Lua language
behavior, chunk contracts, and tiered-execution semantics are unchanged. Hosting and
CLR-interop APIs have breaking changes; see the
[0.22 migration guide](../docs/migration-0.22.0.pub.md).

## Registry-only CLR interop

- The `LuaClrBindingMode` enum and the `BindingMode` option are removed together with the whole
  reflection fallback bridge: member caches, reflection overload selection, reflection
  invocation, reflection-built delegates, the loaded-assembly type scan, and Activator-based
  construction. Every exposed type, constructor, member, and delegate resolves through the
  binding registry; unbound allowlisted types fail with a stable `no registered static binding`
  error, and enabling CLR interop without a registry is a configuration error.
- Steady-state conversions no longer perform runtime reflection lookups: task and value-task
  results, enums, arrays, collections, tuples, and default value-type arguments marshal through
  strongly typed delegates cached per closed type, and binding-registry lookups are lock-free.
- Event subscription uses the bound delegate's real return type instead of assuming void
  handlers.

## Compile-time generated FFI bindings

- The Lunil.StandardLibrary package now ships an FFI binding generator as an analyzer asset.
  `[assembly: LuaFfiGenerateBinding("lib", "symbol", "i32(i32, i32)")]` produces a strongly
  typed native delegate plus an address-resolved invoker for each declared symbol, registered
  through the generated `ILuaFfiBindingProvider`. Bound symbols marshal without runtime
  delegate generation and without per-call `Delegate.DynamicInvoke`, on NativeAOT and trimmed
  runtimes alike. Invalid signatures, unsupported calling conventions, and duplicate requests
  are reported as `LUNILFFI001`/`LUNILFFI002` build diagnostics.

## State-owned runtime operations

- `LuaRuntimeOperations` is a sealed instance service owned by each `LuaState`
  (`state.Operations`). `GetIndex`, `SetIndex`, `Unary`, `Binary`, and `ResolveCall` keep their
  names and behavior and drop their leading state argument; the service captures the state's
  version profile at construction. The generated-code ABI entry points
  (`LuaCodegenAbiV1`-`V5`) keep their exact static signatures.

## Instance-owned engine internals

- Process-wide mutable static state is gone from the runtime, hosting, analysis, and JIT
  backend: per-state services replace attachable caches, heap identities and patch rollouts
  use explicit injectable sources and gates, the Godot and Unity host registries are instance
  classes with one process default (`LuaGodotRuntimeRegistry.Process`), and the JIT's module
  memoization and warmup state belongs to the tier compilers and the tiered registry.
- The configuration-reading standard libraries (basic, io, os, package, debug) install through
  instance modules that own their resolved options; 27 per-call state-service lookups become
  direct field reads. `print` keeps its exact historical shape.
- The tier 0.5 interpreter loop lives inside the reference executor as one cohesive type; the
  reference executor remains a stateless algorithm that can serve any engine.
- The managed JIT resolves its emitted-call method tokens through compile-time-bound delegate
  shapes; the remaining property-getter and constructor lookups are the documented remainder of
  the dynamic-code backend.
- The CLI and language server report versions from compile-time constants instead of reading
  assembly metadata.

## Performance

- Per-version coercion and ordering flags resolve through captured fields on the operations
  service, and interop conversions take lock-free registry reads plus cached delegates, removing
  per-call lookup work from semantic operations and CLR marshalling.
