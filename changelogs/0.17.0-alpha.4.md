# Lunil 0.17.0-alpha.4

## Unannotated semantic analysis

- Metatable-based classes without any annotations now carry instance types end to
  end: calling a constructor member (`X.new(...)`, `X:create(...)`) returns an
  instance whose members resolve through the class table, powering member
  completion, hover types, and go-to-definition on instances.
- `__index` fields are treated as inheritance during member resolution: a class
  table delegating to a parent table exposes the parent's members for completion,
  hover, and navigation without a single annotation comment.
- Fixed captured-table tracking: module and class tables captured by closures
  used to keep their first snapshot (often an empty placeholder), hiding every
  member declared afterwards from member completion, hover, and cross-module
  navigation. Growth updates of one table now replace the previous snapshot.
- Constructor snapshots taken mid-declaration no longer freeze a member-less
  class shape; instances are rebuilt over the receiver when the snapshot carries
  no members.
- The document outline now lists table-assigned functions (`function M.f`,
  `function C:m`, `M.f = function`) with their inferred signatures, so module
  APIs appear in the outline and breadcrumbs without annotations.

## VS Code extension

- The status item now shows the workspace folder name and the indexed module
  count once indexing completes (for example `Lunil · my-game · 214 modules`);
  the count can be disabled with `lunil.statusBar.showModuleCount`.
- Quick fixes gain "Suppress LUAxxxx in this workspace", which updates
  `lunil.server.suppressedDiagnosticCodes` for the workspace (or user profile in
  single-file sessions) and takes effect without a restart; the per-line
  suppression quick fix from the server remains available.
- Configuration pushes to the server now include
  `lunil.server.suppressedDiagnosticCodes`, so suppression changes made outside
  the quick fix also apply immediately.
